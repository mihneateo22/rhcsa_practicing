RHCSA EX200 PRACTICE - DRILLS, 2026-10-18
RH124 chapters 1-6 (help, files and links, redirection, shell
environment, users and groups, sudo, password aging)

ROUTINE FOR EVERY DRILL
  1. Revert the VM to its "clean" snapshot, then run the SETUP commands.
  2. Time limit: 60 minutes (weeks 1-2). Notes are allowed; write down
     the task number every time you open them.
  3. Build /root/check.sh as you go (see HACK 1 at the end).
  4. Reboot, run the checks, and paste the output for GRADE.
  5. Save check.sh to the repo, then revert the VM again.

DRILL 1
======================================================================

SETUP (servera, as root)
  groupadd devs
  useradd -G wheel vlad
  useradd -G devs eva

TASKS

1. Create the following users and groups:
   - A group named ops with GID 3000.
   - Users andrei and ioana, who both belong to ops as a secondary
     group.
   - User mara, who has no access to an interactive shell and is not
     a member of ops.
   - The password for andrei, ioana and mara is Ex200pass.

2. Members of the group ops can run any command as root using sudo,
   and are never prompted for a password.

3. User vlad must also be a member of ops and keep all of his current
   group memberships. Rename the group devs to engineering and give it
   GID 5000. Its existing members must remain members.

4. Passwords of all users created from now on must expire after 60
   days, with a warning 10 days before expiry. Then create user tudor
   with UID 2600. His account expires on 2026-12-31. Separately,
   andrei's password is valid for at most 30 days, and he must set a
   new password the next time he logs in.

5. User eva is leaving the company. She must not be able to log in by
   any method, including SSH keys. Her account and home directory must
   stay on the system.

6. For user ioana only, every new login session must have a command
   ll that runs "ls -lh". Her default editor for programs that read
   the EDITOR variable must be vim.

7. Create the directories /srv/archive/2026/q1 through
   /srv/archive/2026/q4.
   - /opt/current must refer to /srv/archive/2026/q4, and it must work
     no matter which directory you access it from.
   - Create /srv/archive/2026/q4/report.txt containing the text
     "Q4 draft".
   - /srv/archive/latest-report.txt must be a second name for the same
     file, so that if either name is deleted, the content is still
     reachable through the other.

8. /root/sysinfo.txt must contain exactly three lines, in this order:
   1. The running kernel version.
   2. The full RHEL release string.
   3. The number of lines in /etc/services, as a bare number.

VERIFY (after a reboot)

1. getent group ops shows GID 3000. id andrei, id ioana and id mara:
   ops appears for the first two only. getent passwd mara ends in
   /sbin/nologin. To test the passwords, log in as a non-root user and
   run "su - ioana". "su - mara" accepts the password and then prints
   "This account is currently not available". "su - andrei" forces a
   password change (because of task 4).
2. visudo -c reports everything as parsed OK.
   su - ioana -c 'sudo -n id -u' prints 0.
   sudo -l -U vlad also shows the rule (he is now in ops).
3. id vlad lists wheel and ops. getent group engineering shows GID
   5000 with eva listed. getent group devs prints nothing.
4. chage -l tudor shows maximum 60, warning 10, and account expiry
   Dec 31, 2026. id -u tudor prints 2600. chage -l andrei shows
   "password must be changed" and maximum 30.
5. passwd -S eva shows the password as locked. chage -l eva shows an
   account expiry date in the past. getent passwd eva and
   ls -ld /home/eva still exist.
6. su - ioana, then: type ll shows an alias for ls -lh;
   env | grep ^EDITOR prints EDITOR=vim (it must appear in env, not
   only in echo); ls -l ~/.bashrc shows the file is still owned by
   ioana.
7. ls -li /srv/archive/2026/q4/report.txt /srv/archive/latest-report.txt
   shows the same inode and a link count of 2.
   cd /tmp && ls /opt/current/ shows report.txt.
8. wc -l /root/sysinfo.txt prints 3. Line 3 is only an integer (no
   file name after it) and matches the count from wc -l /etc/services.

   gid=4200(auditors). getent group dana prints NOTHING.
   getent passwd dana shows the full name and /srv/dana.
   ls -la /srv/dana shows the skel dotfiles, owned by dana.
2. visudo -c reports OK. sudo -l -U dana lists exactly the two

8. cat /root/passwd-pages.txt shows at least the section 1 and section

HACKS
======================================================================

HACK 1 - Build your reboot check as you go
  After each verify command gives the result you expected, run:
      echo "!!" >> /root/check.sh
  Inside double quotes, bash still does history expansion, so !!
  becomes your last command and is appended to the file. At the end:
  reboot, then run "bash /root/check.sh".
  Trap: double quotes also expand $VAR, $(...) and inner " right now.
  For check commands that contain those, write the line by hand in
  single quotes:
      echo 'echo "kernel: $(uname -r)"' >> /root/check.sh

HACK 2 - Search --help output with grep instead of reading the whole
man page
      tar --help | grep -i gzip
  Trap: a pattern that starts with a dash is read as an option for
  grep itself. Put -e before it:
      tar --help | grep -e '-z'
